给定一个整数数组 `nums`，你最初位于第一个下标，数组中每个元素代表你在该位置**可以跳跃的最大长度**。问能否到达最后一个下标。

直觉上这像一道搜索题：每个位置有多种跳法，枚举所有路径看有没有一条通到底。但正确的思路比这简单得多——整道题只需要一个变量。

## 一、题目的关键：是「上限」，不是「步长」

`nums[i]` 表示**最多**跳 `nums[i]`，也就是说从位置 `i` 出发，你可以跳 1 步、2 步、……、`nums[i]` 步中的任意一种。这个"上限"语义是贪心能成立的前提：从一个位置出发，你拥有它之后的所有落点，而不是只有一个固定落点。

反例是另一类跳跃题（如「跳跃游戏 II」的某些变体或固定步长的格子题），那里选择是排他的，贪心就要另当别论。

## 二、贪心策略：维护能到达的最远位置

我的注释里写的就是全部思想：

> 贪心：维护能到达的最远位置

用一个变量 `farthest` 表示：**遍历到目前为止，考虑前缀 `nums[0..i]` 中所有位置，理论上能抵达的最远下标**。每走到一个新位置 `i`：

- 如果 `i > farthest`，说明这个位置根本到不了——前面所有位置的跳力加起来都够不着它。数组中出现一个无法抵达的点，后面无论它数值多大都与你无关，自然也无法抵达末尾，直接返回 `False`。
- 否则 `i` 可达，用它刷新边界：`farthest = max(farthest, i + nums[i])`。`i + nums[i]` 是从 `i` 出发能碰到的最远下标，而之前积累的 `farthest` 可能更远（比如前面有个很大的数），所以取最大值。
- 每次刷新后顺手检查：`farthest >= len(nums) - 1`，够到末尾就提前返回 `True`，不必扫完整个数组。

## 三、代码逐行对照

```python
def canJump(nums) -> bool:
    farthest = 0                          # 最远可能抵达的位置
    for i in range(len(nums)):            # 遍历每个位置，维护最远可能抵达的位置
        if i > farthest:                  # 当前位置根本到不了
            return False                  # 数组中存在无法抵达的一点，进而无法抵达末尾
        farthest = max(farthest, i + nums[i])  # 维护最远可能抵达的位置
        if farthest >= len(nums) - 1:     # 能否抵达末尾
            return True
    return True
```

**三步的顺序一步都不能换。** 这是最容易写错的地方：`i > farthest` 的判断必须放在更新 `farthest` **之前**。如果先更新，一个根本到不了的位置 `i` 会把它自己的 `i + nums[i]` 加进边界里——用你到不了的立足点去扩展可达范围，答案就错了。先判死、再刷新、够到就提前退出，三步各司其职。

## 四、走一遍两个例子

**`[2,3,1,1,4]` → true**

| i | 进入时 farthest | i > farthest? | 更新后 farthest |
|---|---|---|---|
| 0 | 0 | 否 | max(0, 0+2) = 2 |
| 1 | 2 | 否 | max(2, 1+3) = 4 |
| 2 | 4 | 否 | max(4, 2+1) = 4 |
| 3 | 4 | 否 | max(4, 3+1) = 4 |
| 4 | 4 | 否，且 4 ≥ 4 | 返回 True |

其实在 `i=1` 时 `farthest` 就已经到 4（即 `len(nums)-1`），直接提前返回。

**`[3,2,1,0,4]` → false**

| i | 进入时 farthest | i > farthest? | 更新后 farthest |
|---|---|---|---|
| 0 | 0 | 否 | max(0, 0+3) = 3 |
| 1 | 3 | 否 | max(3, 1+2) = 3 |
| 2 | 3 | 否 | max(3, 2+1) = 3 |
| 3 | 3 | 否 | max(3, 3+0) = 3 |
| 4 | 3 | **是** | 返回 False |

走到下标 3 时它的跳力是 0，边界停在 3 原地不动。到了下标 4，`4 > 3`——末尾这个数字再大也没用，因为你永远站不到 4 上。这就是题目解释里"你总是会到达下标 3"的本质。

## 五、为什么贪心不会漏掉解

用归纳法看 `farthest` 的含义：它永远等于"只看前缀 `nums[0..i]`，任何跳跃方案所能到达的最大下标"。

- 初始 `farthest = 0`，你只能站在起点，成立。
- 假设处理到 `i-1` 时成立。若 `i > farthest`，按归纳假设没有任何方案能到达 `i`，返回 `False` 正确；若 `i` 可达，那么新边界就是旧边界与"从 `i` 再跳到的最远点"的较大者，仍是所有方案的最大可达下标。

因此 `farthest` 不是某一条具体路径的进度，而是**全部可能路径的包络**。贪心没有做任何"短视"的选择——它根本没在多个跳法里选,只是在计算可达集合的上界。这类"维护全局不变量"的贪心，和"每步挑当前最优"的贪心不是一回事，前者几乎没有反例风险。

## 六、复杂度

- 时间：每个位置最多访问一次，O(n)。
- 空间：只有一个 `farthest`，O(1)。

对比朴素 DFS/BFS 的 O(n) 时间但 O(n) 甚至指数级的搜索空间，以及动态规划 O(n²) 的写法，贪心在三个维度上全面占优——代价是需要想清楚上面那节的不变量。

## 小结

1. `nums[i]` 是跳力**上限**，所以从一个位置出发可选的落点是连续的一段，这给了贪心空间。
2. 全程只维护一个不变量：`farthest = 前缀内所有位置合起来的最远可达下标`。
3. 三步顺序不能换：**先判不可达，再刷新边界，够到末尾提前返回**。先更新后判断会把到不了的位置算进边界，是这题最经典的翻车点。
4. 判断到不了时立即 `return False`：一个不可达的点会截断后面的一切，无论它数字多大。
