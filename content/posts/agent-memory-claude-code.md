根据 Lance Martin 等工程团队成员的官方写作，以及 Claude Code 的 **Auto Dream（自动做梦 / 后台整合）** 架构规范，A 社将 Agent 记忆明确定义为“跨会话保留的经验性知识”，范围排除模型权重更新与单次会话内的 Context Compaction。

这套架构的本质，是用“异步离线算力 + 分层文件系统 I/O”去置换“在线推理时的上下文复杂度”。以下基于官方原文实验数据与底层实现，从架构拆解、Token 消耗、任务效率及任务质量四个维度进行具体分析。

## 一、底层架构拆解：四层记忆栈 + 四阶段离线整合

在官方设计中，Claude Code 及 Agent 记忆并非单一的向量数据库（RAG），而是由下至上的**四层文件系统架构（Four-Layer Memory Stack）**：

- **Transcripts（原始会话日志层）：** 存储在本地的 `.jsonl` 原始对话与工具调用流水，只追加不修改，作为事实溯源底座（Ground Truth）。
- **Memory Notes（离散笔记层）：** Agent 在执行任务时，自主判断“未来复用价值（Salience）”并实时写入 `~/.claude/projects/<project>/memory/` 的局部经验，例如踩坑记录、非标构建指令。
- **Memory Representations（结构化表征层）：** 将零散笔记升维组合成特定主题的内部 Wiki 页面或结构化参考文档。
- **Injected Context（常驻注入层）：** 每次新会话启动时预加载的极小切片，例如项目级的 `CLAUDE.md` 与 `MEMORY.md` 索引，严格受限于 200 行以内规则。

**跨层流转引擎（Dreaming / Auto Dream）：** 当满足触发阈值，例如距上次整理超过 24 小时且累计 5 个以上会话时，后台派生只读代码权限的 Sub-agent 执行四阶段离线流转：

**Orientation**（扫描目录建立认知图谱）→ **Signal Gathering**（从 JSONL 日志检索用户纠正与高频模式）→ **Consolidation**（将“昨天”等相对时间转为绝对日期、消除架构迁移后的矛盾条目、合并重复项）→ **Pruning & Indexing**（清理已删除文件的调试记录，压平索引至 200 行内）

## 二、对 Token 消耗的影响：削峰填谷，打破二次方膨胀

在没有分层记忆架构前，长周期 Agent 任务面临致命的 **Token 二次方复合膨胀（Quadratic Cost Compounding）**。每一轮新增的探索日志、报错堆栈，都会在后续每一轮 Turn 中被重复计费。该架构从三个层面重构了 Token 账单。

**在线推理 Token 大幅下降，单问题节省约 20,000 Tokens。** 官方在约 35 万个文件（4.2 亿 Tokens）的内部语料库基准测试中披露：相比单纯依赖实时文件搜索（File Search / Grep），“经过 128 轮 Dreaming 构建的 Wiki 表征 + 搜索”组合，平均每个问题直接节省约 20,000 个在线 Token。Agent 无需每次从零执行宽泛的 `grep-then-read` 试错循环，可以直接命中结构化表征。

**最大化 Prompt Cache 命中率，达到 89%~93% 缓存读取。** 第 4 层（Injected Context）被严格控制在 200 行，约 500~2000 Tokens，且在会话期间静态不变；配合 `.claude/rules/` 的路径作用域，例如前端任务零开销跳过 `src/api/**` 规则，使前缀高度稳定。结合 Claude 5 分钟 TTL 的 Prompt Caching，Agent 循环中 89% 至 93% 的输入 Token 均直接命中缓存。

**引入隐性成本：离线整合开销与“过度记忆”陷阱。** Dreaming 机制并非免费，它把 Token 消耗转移到了后台异步进程。同时，官方在《Pokémon Red（宝可梦红）》实验中揭示了模型能力对 Token 开销的反噬：**Sonnet 3.7** 采取“记下所有可能有用信息”的策略，创建了 **413 份笔记**，连屏幕上随时可见的当前金币、坐标都单独建档，导致大量 Token 浪费在读写和检索冗余记忆文件上；而高代际模型，如 **Claude Fable 5 / Opus 5.5**，具备更强的信息显著性（Salience）判断力，仅维护 **9~10 个核心策略文件，约 43,000 字符**，实现了更高的 Token 效费比。

## 三、对任务效率的影响：消除冷启动探索，构建确定性闭环

官方将记忆的本质定义为“对未来需求的一种预测（A prediction about what the future will need）”。写下一条已验证的事实，意味着预测未来的 Session 可以直接采信该结论，而免去二次验证。

**砍掉重复的“盲目探索期”。** 在多会话软件工程中，无记忆 Agent 每次重启都需要花费数十个 Tool Use 轮次去探测非显式约定，例如特定的测试启动参数、反直觉的框架改造。通过 Auto Memory 捕获这些经验后，后续会话可以直接跳过探索期进入编码执行。官方实测，在复杂任务中配合规划模式，可将 35 分钟以上的试错缩短至 12 分钟左右。

**避免状态死锁与无效循环。** 在长程状态追踪测试《Pokémon Red》中，过度记录的 Sonnet 3.7 把大量算力和动作步数消耗在管理数以百计的碎片文件夹上，最终仅拿到 **1 枚徽章**；而仅保留高价值目标与规则的 Fable 5 依靠精简记忆快速推进，拿到了 **4 枚徽章**。

**架构级自愈阻断“连环踩坑”。** 官方原文记录了一个典型案例：在一次运行中，Agent 留下了一条错误笔记，误将月见山 Mt. Moon 另一侧标记有宝可梦中心。在未开启 Dreaming 时，Agent 盲信该笔记，**连续三次从同一个悬崖跳下陷入死循环**，始终无法抵达华蓝市（Cerulean City）；开启离线 Dreaming 后，后台进程通过比对原始 Transcript 发现轨迹异常并修正了这条错误笔记，下一轮会话随即顺利通关。

## 四、对任务质量的影响：抗上下文腐败与跨会话持续学习

长会话质量下降的核心原因并非模型退化，而是**上下文噪声（Context Noise）与记忆腐败（Memory Rot）**。过期日志、互相矛盾的历史指令稀释了注意力机制（Attention Dilution）。官方通过多项基准测试量化了该架构对任务质量的提升：

| 测试基准 / 评估场景 | 无记忆 / 传统检索基线 | 启用分层记忆 / Dreaming 后 | 核心质量增益机制 |
| --- | --- | --- | --- |
| CL-Bench 1.0（Opus 5.5） | 0.655 | **0.838**（+27.9%） | 形成“记录失败 → 提出假设 → 验证并固化为规则”的完整闭环 |
| CL-Bench 1.0（Opus 4.7） | 0.383 | **0.700**（+82.8%） | 将散乱的猜测整合为单一参考文档，明确标注已验证与未验证事实 |
| 文档问答评分（Rubric Pass Rate） | 13% | **48%**（+35 pct） | Dreaming 离线构建主题 Wiki，消除跨文档碎片化信息断层 |
| 法律并购案综合推理（24 问） | 73%（仅文件搜索） | **87%**（检索 Dreaming Wiki） | 跨多文档的隐含逻辑在离线阶段已被预先合成与交叉校验 |
| 35 万文件内部库问答 | 54%（仅搜索） | **61%**（128 轮 Dreaming Wiki + 搜索） | 过滤历史废弃方案，大幅降低大型代码库/文档库中的幻觉率 |

## 三个关键工程洞见

1. **构建验证闭环（Closing the Learning Loop）。** 在 CL-Bench 1.0 数据库连续问答测试中，较弱的模型，例如 Sonnet 4.6，只会在目录里留下一堆未经证实的猜测，质量提升微乎其微；而 **Opus 5 / 5.5 和 Sonnet 5.5** 能够独立完成“闭环”——它们的每条记忆不仅包含总结出的规则，还附带“该规则为何成立的验证证据”以及“此前踩过的陷阱警告”，使后续会话的推理具备高度确定性。

2. **自主显著性判断优于人工硬编码规则（Let the model decide salience）。** Anthropic 实验发现，当人类工程师强行在 Prompt 中规定死板的记忆法则，例如硬性要求模型“只允许记录失败教训（Record only failures）”时，**Opus 4.7 和 Opus 5 的记忆增益反而大幅缩水**。对于前沿高能力模型，只声明“记忆的用途”并放权让其自主判断哪些信息值得持久化，任务质量最高。

3. **架构局限性：Session Memory 的盲区。** 官方同样说明了该架构的边界：常驻注入层（Injected Context）一旦混入一条未被清洗的错误笔记，就会像病毒一样污染所有新建会话；此外，基于会话的记忆“只能记住 Agent 亲眼见过的东西”。团队在工单系统、Slack 讨论或 PR Review 中达成的外部架构妥协，若不通过外部共享上下文层（Shared Context Layer）或手动更新 `CLAUDE.md` 注入，单机自演进的 Agent 无法感知。
